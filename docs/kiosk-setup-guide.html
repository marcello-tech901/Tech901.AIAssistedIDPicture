Prerequisites Before you begin

The kiosk app is a self-contained Windows application—no .NET runtime installation is needed. Just make sure you have:

  • Windows 10 or 11 (x64). The app targets win-x64 only.
  • A webcam connected to the machine (USB or built-in).
  • Administrator access to the kiosk machine (needed to set environment variables and trust the certificate).
  • Azure credentials (optional). You’ll need the Speech and Face API keys if you want voice interaction and intelligent face-based photo cropping. The app works without them—see Step 4.
2

Download & Extract Get the publish package

Download the latest release ZIP from the repository’s Releases page (or from the shared link you were given). The file will be named:

filename 
Tech901-IdPhoto-{version}-win-x64.zip

Extract the ZIP to a location on the kiosk machine. We recommend:

Recommended path 
C:\Tech901\IdPhoto\
ℹ
Automated install option If you have the repo cloned, you can use the installer script instead of extracting manually. Run the following in an elevated (Administrator) PowerShell terminal:
PowerShell (Administrator) 
# Extracts ZIP, creates desktop shortcut, optionally sets up auto-start
.\infra\Install-Kiosk.ps1 -SourcePath .\Tech901-IdPhoto-1.0.0-win-x64.zip -AutoStart

Trust the Application SmartScreen & certificate

⚠
This app is signed with a development certificate The executable is Authenticode-signed, but the certificate is not issued by a public Certificate Authority. Windows SmartScreen will flag it as an unrecognized app on first launch. This is expected and safe—the cert is an internal Tech901 development signing certificate.

When you first launch Tech901.IdPhoto.App.exe, Windows will show a SmartScreen warning. Follow these steps to proceed:

4

Configure Azure Services Environment variables

The kiosk uses two Azure Cognitive Services. Both are optional—the app runs fine without them, but with reduced functionality:

🎤 Speech Service Voice prompts & spoken name capture. Without it, participants type their name manually.
📷 Face API Intelligent face-centered photo cropping. Without it, photos are center-cropped instead.

Azure credentials are provided as machine-level environment variables. Set them in an elevated PowerShell terminal:

PowerShell (Administrator) 
# Speech Service
[Environment]::SetEnvironmentVariable("Azure__Speech__Key",    "<your-speech-key>",      "Machine")
[Environment]::SetEnvironmentVariable("Azure__Speech__Region", "eastus",                "Machine")

# Face API
[Environment]::SetEnvironmentVariable("Azure__Face__Key",      "<your-face-key>",        "Machine")
[Environment]::SetEnvironmentVariable("Azure__Face__Endpoint", "<your-face-endpoint>",   "Machine")
↻
Restart required After setting environment variables, you must restart the kiosk app (or log off and back on) for the new values to take effect.

Full environment variable reference:

Variable Name Description Required
Azure__Speech__Key Azure Speech Service subscription key Optional
Azure__Speech__Region Azure region (e.g. eastus) Optional
Azure__Face__Key Azure Face API subscription key Optional
Azure__Face__Endpoint Face API endpoint URL Optional
💡
Automated config option If you have the repo cloned, you can use the installer script with the -ConfigureAzure flag, which will prompt you for each key interactively:
.\infra\Install-Kiosk.ps1 -SourcePath .\*.zip -ConfigureAzure
5

Run the Kiosk Launch the application

Double-click Tech901.IdPhoto.App.exe from the install directory (or the desktop shortcut if you used the installer). The kiosk will launch in full-screen mode and begin the idle state, waiting to detect a participant.

✓
What to expect on first launch The app will log which Azure services are active. If keys aren't configured, you'll see log messages like “Azure Speech not configured — using NullSpeechService”. This is normal—the kiosk is running in offline mode with keyboard input and center-crop.

The kiosk workflow is fully automatic for participants:

Idle → Name Capture → Roster Match → Positioning → Capture → Review → Processing → Complete

Verify & Troubleshoot Confirm everything works

If you have the repo cloned on the kiosk machine, you can run the diagnostic script to verify Azure environment variables are set correctly:

PowerShell 
.\infra\Test-AzureConfig.ps1

Expected output when everything is configured:

Output 
[OK]   Azure__Speech__Key    = ab12****  (Machine)
[OK]   Azure__Speech__Region = east****  (Machine)
[OK]   Azure__Face__Key      = cd34****  (Machine)
[OK]   Azure__Face__Endpoint = http****  (Machine)

All Azure environment variables are set.

Common issues:

?
Variables show as [MISSING] You either skipped Step 4, the PowerShell session wasn't elevated (Administrator), or you haven't restarted after setting them. Environment variables set at the “Machine” scope require a new process to pick them up.
?
Camera not detected Make sure the webcam is plugged in and recognized by Windows (check Device Manager). The kiosk uses OpenCvSharp4 and will select the default camera device.
?
App still shows SmartScreen warning after trusting The certificate must be added to the Local Machine Trusted Root CA store, not the Current User store. Use an elevated PowerShell to import it, or ask the package provider for the trust script.
📄
Application logs Logs are written to the logs/ directory inside the install folder. Look for idphoto-{date}.log files for detailed diagnostic information.
